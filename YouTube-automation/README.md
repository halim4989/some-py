---
## Overview

This project automates YouTube video editing using Python.  
It downloads a video in a **specific resolution**, separates the **audio**, **splits** the video at a given timestamp (to the nearest **keyframe**), and then **merges** it with another audio track — all without re-rendering the video.

> 💡 Because the splitting is done on keyframes, the process is **super fast and lossless**.

---


## What this script does

- Reads `file.txt` (each line contains a YouTube URL and a short name separated by ` === `).  
- For each entry it:
  1. Downloads the video stream (tries **1080p**, falls back to **720p**).  
  2. Downloads an audio-only stream.  
  3. Merges the downloaded video and audio into a single file using `ffmpeg` (produces `tmp/out.mp4`).  
  4. Concatenates `tmp/out.mp4` with a static `outro.mp4` using an ffmpeg concat list (`tmp/concat.txt`) and saves the result to `out/<name>.mp4`.

> The script also downloads an `outro.mp4` when run directly (see bottom of `yt-auto.py`).

## Required repository structure

```
project/
├── yt-auto.py

├── tmp/                # temporary downloads & ffmpeg intermediate files (deletes and creates for each video)

│   ├── aud.acc         
│   ├── out.mp4
│   └── concat.txt      # generated by the script
└── out/                # final processed videos are written here (out/<name>.mp4)
```

Make sure the `tmp/` and `out/` folders exist or allow the script to create files inside them.

---

##  `file.txt` format

Each line must be:
```
<YouTube URL> === <output_name/video_name>
```

Example:
```
https://www.youtube.com/watch?v=abc123 === my_first_clip
https://www.youtube.com/watch?v=def456 === second_clip
```

The script processes up to the first 15 entries by default (`urls[:15]`).

##  Run the script

```bash
python yt-auto.py
```

When run directly, the script first downloads an `outro` video (hardcoded URL in `__main__`), writes `tmp/concat.txt`, then processes the entries from `file.txt` and writes final files to `out/<name>.mp4`.

##  Key ffmpeg commands used (from code)

- Merge video + audio (no re-encoding):
```
ffmpeg -y -i ./tmp/vid.mp4 -i ./tmp/aud.acc -c copy -shortest ./tmp/out.mp4
```

- (Not active in the final flow) Example cut command (note: two `-ss` flags):
```
ffmpeg -y -ss 4 -i ./tmp/out.mp4 -ss 1.9 -c copy "./out/<name>.mp4"
```
- Concat using a file list (the script writes `tmp/concat.txt`):
```
ffmpeg -y -f concat -safe 0 -i ./tmp/concat.txt -c copy "./out/<name>.mp4"
```

**Notes**:
- `-c copy` avoids re-encoding (fast and lossless) and is compatible with concatenation when container/codec parameters match.  
- The `-ss` before/after `-i` is the two-step seek technique (fast input seek + accurate output seek). The cut command is present in code but commented out in final flow.

---

## 🧩 Why Two `-ss` Flags in FFmpeg?

Using two `-ss` flags is a common **two-step seek technique**:

| Flag | Placement | Description | Speed | Accuracy |
|------|------------|-------------|--------|-----------|
| `-ss` (before `-i`) | Input-level seek | Fast but may be inaccurate | ⚡ Very Fast | ❌ Rough |
| `-ss` (after `-i`)  | Output-level seek | Accurate, decodes keyframes | 🕒 Slower | ✅ Precise |

➡️ **Combining both** gives you **speed** + **accuracy** for precise, efficient cutting.

## ⚠️ Future Work

- The script names the downloaded audio `aud.acc` which may be a typo: Pytube usually provides audio in formats like `webm` or `mp4` (aac). Ensure the extension matches the downloaded stream (or use the stream's `default_filename`/mime subtype).  
- The script currently concatenates `tmp/out.mp4` with a hardcoded `outro.mp4` (downloaded at runtime). Modify `tmp/concat.txt` logic if you need different behavior.  
- Error handling is minimal — `run_cmd` prints stderr on failure. Consider adding retries and better file-existence checks.  
- Concatenation requires compatible codecs/containers — mixing different codecs will fail or require re-encoding.
